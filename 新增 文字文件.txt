個人期末專題：自行訂定主題之網頁開發（含前後端）
專題方向
自行訂定專案主題，並規劃技術選型。
完成前後端串接，實作完整的 CRUD 功能（Create, Read, Update, Delete）。
將整體專案以文件、圖示與 Demo 影片方式清楚展示與說明。
專題方向與要求
主題自訂
可自由訂定主題，只要該主題能體現出 CRUD 功能以及前後端整合即可。
主題範例（僅供參考，非限制）：
線上商品展示與管理平台
活動報名與參與者資料管理系統
餐廳點餐與訂單管理系統
社群網站內容分享平台
重點：系統需提供使用者視覺化的前端介面，並透過後端 API 進行資料創建、讀取、更新、刪除的操作。

資料庫設計與建立
使用 MongoDB。
根據專案主題與資料需求設計資料庫表格（或集合）結構。
確保資料表結構、欄位設計能符合 CRUD 操作的需求。
後端開發
可使用任意後端框架（XAMPP 除外，其架構過舊且存在資安風險）。
設計對應 CRUD 的 API 端點。
API 端點範例（[resource] 請依專案主題替換，如 products、users、orders 等）：

POST /api/products # 新增商品資料（Create）
GET /api/products # 取得所有商品（Read all）
GET /api/products/:id # 取得特定商品（Read single）
PUT /api/products/:id # 更新商品資料（Update）
DELETE /api/products/:id # 刪除商品資料（Delete）

需要有統一的回應格式，並妥善處理錯誤狀況與 HTTP 狀態碼。
前端開發
可使用任意前端框架（React、Vue等）。
鼓勵使用現代化前端框架，以學習元件化開發與狀態管理。
開發前端使用者介面，並將功能元件化。
實現基本互動與導覽介面，使用者需能透過前端操作執行 CRUD 功能。
串接後端 API，於前端顯示資料並提供操作介面（如表單輸入、按鈕點擊、清單瀏覽）。
樣式設計可靈活運用 CSS、CSS 框架（Bootstrap、Tailwind）或 UI 元件庫（Material UI）。
版本控制與專案發布
Git 版本控制
使用 Git 管理程式碼版本，至少需使用基本指令：
  git init
  git add
  git commit
  git push
需有至少 5 次以上的 commit 紀錄，展現開發過程。
Commit 訊息需清楚描述變更內容（中英文皆可）。
使用有意義的 commit message，例如：
feat: 新增商品列表頁面
fix: 修正刪除功能錯誤處理
docs: 更新 README 安裝說明
部署
前後端以本機部署為主。
請提供本機執行的清晰說明文件及操作步驟，以便助教測試。

README 文件
說明專案主題與目標、技術選擇原因、架構說明、安裝與執行指引。
API 規格說明文件
列出各 API 的路由、HTTP 方法、參數、回應格式範例。
架構圖與流程圖
架構圖：展示前端、後端與資料庫的整合方式。
CRUD 流程圖：描述使用者在前端操作後，資料透過後端 API 流向資料庫並回傳的流程。
報告及 Demo 影片（5~8 分鐘）
演示系統主要功能與使用流程，包括新增、查詢、更新、刪除數據的步驟。
